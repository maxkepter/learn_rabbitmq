Bài tập nâng cao RabbitMQ

Hẹn giờ (Delayed) + Dead Letter Exchange (DLX) + Retry Pattern

🎯 1. Mục tiêu

Xây dựng một hệ thống gửi thông báo theo lịch hẹn bằng RabbitMQ, áp dụng các kỹ thuật cốt lõi:

TTL (Time-To-Live) Dead Letter Exchange (DLX) Direct Exchange Queue Binding Consumer Acknowledgment Retry Logic Structured Logging

📋 2. Tổng quan bài toán

Xây dựng hệ thống gửi email nhắc nhở hoặc thông báo theo thời gian chờ với luồng xử lý sau:

  1. Producer: Tạo message chứa thông tin người nhận, tiêu đề, nội dung, thời gian chờ.
  2. Queue tạm (TTL): Message được đưa vào queue tạm thời có cài đặt TTL.
  3. Dead-lettering: Sau khi TTL hết hạn, RabbitMQ tự động chuyển message sang Exchange chính.
  4. Routing: Exchange định tuyến message sang queue đích.
  5. Consumer: Đọc message từ queue đích, xử lý nội dung và ghi log.
  6. Retry/DLQ: Nếu xử lý thất bại, message được đưa vào hàng đợi Retry hoặc Dead Letter Queue.

⚙️ 3. Yêu cầu kỹ thuật

Topology RabbitMQ

Thành phần Tên Cấu hình / Thuộc tính
Exchange main_exchange Type: direct, durable: true
Queue gốc (Delay) delay_queue_10s
durable: true
x-message-ttl: 10000
x-dead-letter-exchange: "main_exchange"
x-dead-letter-routing-key: "go"
Queue đích delayed_target_queue
durable: true
Binding: main_exchange (routing key: go)
Queue Retry retry_queue
durable: true
x-message-ttl: 5000
x-dead-letter-exchange: "main_exchange"
x-dead-letter-routing-key: "go"
Queue Dead-Letter dead_letter_queue durable: true (Lưu message lỗi vĩnh viễn)

Producer: delay_send.js

  • Kết nối RabbitMQ qua biến môi trường.
  • Gửi ít nhất 3 message khác nhau vào delay_queue_10s.
  • Cấu hình message: persistent: true.
  • Ghi log: thời gian gửi, payload, queue đích.
{
  "email": "customer@example.com",
  "subject": "Thông báo nhắc nhở",
  "message": "Bạn có một công việc sắp đến hạn.",
  "retryCount": 0,
  "scheduledAt": "2026-08-19T10:00:00.000Z"
}

Consumer: delay_consume.js

  • Lắng nghe queue delayed_target_queue.
  • Parse payload JSON, hiển thị thời gian nhận, thông tin email, tiêu đề, nội dung.
  • Giả lập các tình huống:
    • Thành công: gọi ack()
    • Thất bại: gọi nack() / reject() hoặc chuyển queue

Cơ chế Retry Logic:

• Nếu retryCount < 3: Tăng retryCount lên 1 và đẩy vào retry_queue (TTL 5s sau đó dead-letter lại về queue đích).

• Nếu retryCount >= 3: Đẩy vào dead_letter_queue để lưu trữ vĩnh viễn và dừng retry.

📁 5. Gợi ý cấu trúc file

  • delay_setup.js — Khởi tạo topology (exchanges, queues, bindings)
  • delay_send.js — Producer gửi message
  • delay_consume.js — Consumer xử lý retry & dead-letter
  • .env — Biến môi trường kết nối (RABBITMQ_URI=...)
